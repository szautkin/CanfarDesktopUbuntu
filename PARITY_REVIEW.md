# Verbinal ↔ CanfarDesktop — Remaining Parity Gaps

_Date: 2026-07-07 · Verbinal HEAD: commit `7396c0b` · Reference: CanfarDesktop 1.3.1_

Verbinal (Rust / GTK4 / libadwaita) is a native-Linux clone of the CanfarDesktop WPF/WinUI reference app. As of this sweep it has reached roughly 1.3.1 feature parity across most surfaces: the Portal/dashboard, the CADC search + ADQL subsystem, the VOSpace storage browser (with a sharing UI the reference lacks), the FITS viewer, the 3D cube viewer, the local Jupyter kernel + notebook editor, the workflows subsystem, and a working MCP transport with a read-tool subset are all ported and largely functional.

This document is the residual-gap checklist the team works from. It compares the current Verbinal against the Windows reference **on function, not pixels** — a GTK4/Adwaita reimplementation is not expected to reproduce WinUI widgets (TeachingTip, Pivot, SelectorBar, SwapChainPanel) exactly, and several intentional Linux-native divergences are called out in the final section rather than counted as gaps. Every itemized missing item from the per-area reviews is preserved below in the "Detailed findings by area" section; severity (`high`/`medium`/`low`) and effort (`S`/`M`/`L`/`XL`) tags are carried through verbatim.

## Notes & platform caveats

Cross-cutting notes on intentional Linux/GTK divergences, things that cannot be 1:1, and per-area verification caveats. Items here are **not** counted as gaps.

**General.** Verbinal is a GTK4/libadwaita reimplementation of a WinUI/WPF app, so exact-widget parity (TeachingTip, Pivot, SelectorBar, synced NumberBox+Slider, TabView add/reorder, ContentDialog, SwapChainPanel) is not expected — every area was graded on function, not pixels. Reference is CanfarDesktop 1.3.1; findings are from reading current Verbinal `src/` (no `cargo build`/runtime re-verification unless noted).

**Portal / Dashboard.** Verbinal intentionally DIVERGES for the better in a few places, none counted as missing: a per-type filter dropdown on the session list, a richer SessionCard (in-use CPU/RAM, FLEX badge), and a dashboard TemplateManager the reference lacks. The two highest-impact items are functional, not cosmetic: batch jobs can be viewed but never submitted, and headless jobs leak into the Active Sessions strip and the 3-session cap. The flexible-vs-fixed launch-payload divergence (sending default cores/RAM instead of 0) is a subtle behavioral bug worth confirming against the live Skaha API.

**Search.** VizieR is NOT a Search-page feature in the reference — VizierService is consumed only by MCP (VizierConeSearchTool) and AiGuideCatalog, so its absence is an AI-assistant/MCP gap that also breaks a shipped Verbinal workflow protocol. The task's mention of "Copy as Python / Jupyter" export is partly speculative: the reference has NO copy-as-python or Jupyter export for search — its results export is CSV/TSV only, which Verbinal matches. Intentional/aligned divergences: (a) data-train caching uses the shared cache_service with TTL + stale-serve + health tracking (more robust than the reference's ad-hoc `datatrain_cache.json`); (b) recent-search dedup by ADQL and saving raw-ADQL runs too; (c) INTERSECTS argument order is swapped but semantically symmetric. The single true bug (not a missing feature) is the filter/sort key-vs-header mismatch (item 1), CONFIRMED by code.

**Storage.** The VOSpace browser is the primary surface and is at or above reference parity; the sharing UI is a Verbinal-only addition (the reference exposes ACLs only via MCP). Scope-aware `projects/<group>` storage is absent but the reference UI doesn't expose it either (MCP-only), so its UI-parity impact is low. Reference LocalFileService.Move and folder rename are not user-wired on the reference side either, so VOSpace folder move/rename is deferred on both.

**Research.** Platform caveats that make this legitimately different rather than a straight port: the reference detail page + download flow depend on WinUI FitsSniff + Cube/FITS viewer wiring and a Windows FolderPicker/FileSavePicker; note storage uses Microsoft.Data.Sqlite FTS5 — a Rust/GTK port would use rusqlite (bundled-sqlite FTS5) + GTK FileDialog. The "purge missing-file records" divergence in observation_store.rs is a behavior change (data loss on offline volumes) that should be reconciled with the reference's deliberate keep-metadata policy regardless of the larger features.

**Image Discovery.** Platform mappings for the port: Windows PasswordVault → Verbinal's existing keyring v3 (reuse with a host:username account key); WinUI ContentDialog + virtualized ListView → GTK4 dialog with a Gtk.ListView/filter model (the reference virtualizes for the huge dpkg/rpm value lists); embedded resources → `include_str!`/`include_bytes!` of probe.sh + inspector.sh (both bash+python, platform-independent, reusable near-verbatim; HomeSubdirectory is already `.verbinal`). The session launch path already supports the two hardest primitives (cmd/env form fields + `x-skaha-registry-auth`), so the launcher facade mostly needs a list-return shape and a headless job-status listing. **Wire-contract divergence to preserve:** MCP uses verbatim capital-ID keys (`imageIDs`/`imageID`) to match the macOS reference — a Rust port must NOT camelCase them. This is a clean, self-contained ~3200-line C# subsystem + ~22KB of scripts: a large but well-bounded greenfield port.

**FITS viewer.** Colormap set diverges rather than lags — Verbinal drops the reference "Cool" map but adds Plasma/Inferno/Magma/CoolWarm and a Histogram-Eq stretch (net superset, not a gap). RA/Dec formatting differs cosmetically but is functionally equivalent. Coordinate persistence uses `~/.local/share/verbinal/fits_bookmarks.json` (directories crate) vs reference LocalFolder `saved_coordinates.json` — behavior parity. gtk::Notebook (manual close buttons) vs WinUI TabView (add-tab, drag reorder) — functional close/switch works; reorder/add-button are cosmetic. The biggest coherent gap is the multi-image comparison suite (WCS-aligned blink, sky-based linked crosshair, sync zoom, approx-WCS banner): the primitives (per-tab WCS, north_angle, pixel/world mapping) all exist, so these are wiring/compositing work, not new math.

**Cube viewer.** The reference renderer is D3D11 on a WinUI SwapChainPanel; Verbinal correctly reimplements it as OpenGL 3.3 GLArea (GPU teardown/resize/DPI handled by GLArea realize/unrealize — not gaps). PDF/PNG writing is reimplemented in helpers/pdf_writer.rs (parity with PdfImageWriter.cs) and works for the slice path — the gap is the plate/volume content fed into it, not the writer. Verbinal spectrum extraction stays in normalized [0,1] space (the panel self-scales, so shape is fine, but this compounds the normalization-cut issue if physical flux is ever surfaced). The recents display-name is the file stem vs the reference's OBJECT/tab-header name — cosmetic. `cube_axes.rs`, `transfer_function.rs`, `cube_colormaps.rs`, `cube_math.rs`, `cube_slice.rs`, `cube_wcs.rs` are all well-tested 1:1 ports — the axes overlay is fully implemented and only needs wiring, so the overlay/spectral-scale items are largely integration, not new algorithms.

**Notebook.** Verbinal's interrupt is genuinely better on Linux — it sends SIGINT to the harness (which catches KeyboardInterrupt and stays alive), whereas the reference must kill+restart the whole process because Windows has no child-process SIGINT. Not a gap. Per-tab kernel ownership, the harness protocol, the boundary sentinel, python discovery, and recent-notebooks are at parity. The real gaps cluster in the DATA-SAFETY lifecycle (dirty-close prompt + autosave + recovery — highest-impact, since the close button currently loses unsaved work silently) and the AGENT surface (the entire MCP notebook tool family + state + applier + target resolver). The recovery i18n strings exist but are orphaned — recovery was scaffolded in translations only.

**Workflows.** The local + built-in subsystem (model, format, store, page, 7 templates) is complete and closely matches the reference. Verbinal's VOSpace service already exposes list_nodes/create_folder/upload_file/download_file, so the VOSpace tier and publish are wiring work, not new plumbing. `WorkflowSource::VoSpace` is defined but dead. The store is intentionally stateless (no Changed event); together with the missing MCP tools this means there is currently no path for an external agent to read/follow/author/check-off workflows and no live "follow the agent" refresh.

**AI / MCP.** Tool-count parity: reference exposes ~111 built-in tools + 3 macOS aliases; Verbinal exposes 16 built-ins (11 read + 5 write) plus dynamic user guide tools — roughly 95 tools missing. The write half being inert end-to-end (no apply path/UI) is the single highest-impact gap. Structural note: the reference's JsonReadTool/JsonWriteTool/AliasedTool base classes have no 1:1 Rust analogue (Verbinal uses flat module dispatch) — architecture, not missing features — but the AliasedTool NAMES are absent because their underlying VOSpace tools are absent. The transport/handshake/router-gate/read-subset foundation is a faithful, test-covered port.

**AI Guide / AI Compute.** Intentional platform divergences (not gaps): Verbinal backs AI Guide state with a single JSON file instead of the reference's SQLite store, dropping the sync-only columns (version/deviceID/deletedAt) — behaviorally equivalent for a single-device app; the registry secret would live in the OS keyring (libsecret) rather than PasswordVault; Fluent glyphs and WinUI ThemeResource brushes don't port (the GTK page legitimately uses libadwaita groups/icons). Genuinely at parity: the AI-Guide description-override + guide-tool READ path (tools/list substitution + guide-tool call), slug/validation/caps, and the AI Connect wizard.

**Settings / cross-cutting.** Intentional divergences: restart-to-apply for language matches the reference's platform behavior (GTK can't re-translate built widgets); Verbinal's per-service health tracker + degraded banner + header popover is arguably richer than the reference's binary NetworkMonitor (the only true miss is the instant OS offline hint); the adw ViewSwitcher reasonably substitutes for the reference's SectionText subtitle + dedicated Home button (treated as present-equivalent). Harbor/registry secrets would use libsecret rather than PasswordVault (relevant only once Image Discovery / AI Compute panels are built). Strong signal across areas: the localization sweep pre-populated catalog.rs with keys for features that were never wired (`MainWindow_OfflineHint`, `Landing_SignInToAccess`, `Tile_AiAssistant_*`, `Settings_ProbeOk/Fail`, `About_Version`, `Research_Export*`, `Nb_Recover*`, `Storage_MenuOpenCube`, `Discovery_*`) — several gaps are "string staged, UI missing," and the wiring is the remaining work.

**Export subsystem.** The task framing "Copy as Python / export to Jupyter" maps, in the reference, to AnalysisNotebookBuilder + `create_analysis_notebook` (an observation→astropy notebook generator) — there is NO literal "Copy as Python" clipboard command in the reference either. Verbinal already has `.ipynb` save-as-format and CSV/TSV results export at parity; the gap is specifically the Claude-friendly BUNDLE pipeline, its Research/Search markdown+JSON builders (SCI-9-2 proposal-citation + SCI-9-3 resolver-provenance), the export UI, the `export_research_bundle` MCP tool, and the astropy analysis-notebook generator. Cargo.toml has no zip crate — a bundle port needs one added; effort is reduced by the existing VOSpace upload_file/create_folder primitives.
