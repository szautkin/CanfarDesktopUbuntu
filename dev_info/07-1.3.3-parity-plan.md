> **Status:** Phases 0–5 are **complete**. The tool surface advertises **137 of the reference's 137
> names** — full name parity, and the `NOT_YET_PORTED` backlog is empty. `cargo fmt`,

## 4. The plan

Ordered so that each phase leaves the tree shippable, and so the "100% MCP UI coverage" goal lands first.

### Phase 0 — Land the WIP (S) — **DONE**
Landed in four commits: the in-flight sweep, the 1.3.3 QA fixes, a tree-wide `cargo fmt`, and a
hygiene pass that made `cargo clippy -- -D warnings` pass for the first time on this branch.

Clearing the lint noise surfaced two real defects it had been hiding:
- **The stdio bridge test was talking to the developer's running app.** It isolated itself with
  `$XDG_RUNTIME_DIR`, but `socket_path()` deliberately ranks the uid-derived `/run/user/<uid>` higher
  (so the bridge still finds the app when a launcher strips the environment). On any systemd host the
  override did nothing. Added `VERBINAL_MCP_SOCKET`, an explicit full-path override that beats every
  other rule, and pointed the test at it.
- **`filter_to_adql` was compiled twice** — `search_page.rs` pulled it in via `#[path]` while
  `helpers/mod.rs` already declared it, so its 8 tests ran in duplicate. (This is why the unit count
  reads 849 → 841 across those commits; no coverage was lost.)

### Phase 1 — Wire-contract parity (M) — **DONE**
All 14 tools renamed to the reference's names, `clear_user_site` implemented, and the 3 macOS aliases
added — **113 tools advertised**. 108 payload keys plus 8 `required` entries converted to camelCase.

The contract is now enforced rather than asserted: `data/canfardesktop_1.3.3_tools.txt` holds the
reference's exact 137-name manifest, and a test diffs ours against it three ways — nothing extra,
nothing missing outside a documented `NOT_YET_PORTED` backlog, and no backlog entry that is secretly
already implemented. **That backlog may only shrink**; it currently holds exactly the 24 tools Phases
2, 3 and 5 will add, so those phases tighten the test automatically as they land.

Two things worth knowing for later work:
- Renaming the tools also renamed the ops sent over the viewer bridge (the notebook and FITS hosts map
  a tool name straight through as its op). `run_all_cells`, `clear_cell_outputs` and
  `list_fits_bookmarks` would have silently failed; the host arms were aligned so tool names and bridge
  ops remain one vocabulary. **Any future tool rename must check the bridge hosts.**
- `str_arg` existed in 11 copies, with six sibling accessors scattered similarly, all reading
  `args.get(key)` directly. They are now one implementation in `mcp::tools` routing through a single
  style-tolerant `arg()`, so a caller may send either `publisherId` or `publisher_id` — matching the
  reference's case-insensitive deserialization, and keeping every pre-rename caller working.

### Phase 2 — Search MCP full UI coverage (XL) — **DONE**
All 15 tools shipped; advertised tools 113 → 128. Thirteen forward over the view-state bridge to the
live page (new `"search"` target) so an agent drives the same widgets a user does; the handler lives in
`ui::search_page::mcp`, a child module of the page (hence `search_page.rs` → `search_page/mod.rs`,
mirroring the reference's `SearchPage.Mcp.cs` split). `remove_recent_search` /
`clear_recent_searches` are Destructive proposals, and the former pins a stable
`(searchedAt, summary)` key at propose time — with a test proving that a list which shifts between
propose and apply still deletes the right entry.

The four blocking defects were fixed first (S2–S5). Two turned out to be worse than the audit said:

- **Reset never cleared the facets**, so constraints that looked cleared silently narrowed the next
  search. `reset_search_form` depended on it.
- **Pixel-scale parity carries a behaviour change**: a bare value now means `= v`, not `<= v`. Verified
  against the reference (`AddConvertedRangeClause`, `RangeOperand.Equals`) — our `<= max` was the
  divergence. Both behaviours are now pinned by tests.

Three supporting fixes fell out, each closing a real bug:
- `DataTrainManager::set_all_selections` — restoring by replaying toggles would clear downstream
  columns and wipe the very selections being restored.
- `SearchStoreService::save_all_recent` — the sidebar's delete button cleared and re-saved entry by
  entry, which reversed the order and merged entries sharing ADQL.
- `SearchFormState` gained a container-level `#[serde(default)]`: it is persisted inside every recent
  search, so without it adding one field made every saved search fail to parse and vanish silently.

Also worth carrying forward: the first version of these tests would have **deleted the developer's own
recent searches**, because `SearchStoreService::new()` points at the real user data dir. It now has a
`with_data_dir` constructor and every test uses a temp store.

### Phase 3 — FITS + Cube MCP full UI coverage (L) — **DONE**
Seven new tools (`switch_fits_tab`, `blink_fits_tabs`, `set_cube_transfer`, `show_cube_spectrum`,
`get_cube_channel_profile`, `switch_cube_tab`, `list_recent_cubes`) plus the 1.3.3 extensions to
`set_fits_view` and `get_fits_view`. Advertised tools 128 → 135.

The audit this phase was "blocked on" proved unnecessary — reading the reference's `27a4889` diff for
those files directly was faster and more targeted. The blink and sync machinery already existed from
the earlier sweep; this exposed it.

**Four real bugs surfaced, three of them invisible:**

1. **Every renamed argument was being ignored.** Phase 1b moved schemas to camelCase but only touched
   `src/mcp/tools`; the three viewer hosts still read `min_cut`, `north_up`, `center_x` and friends.
   `set_fits_view {"minCut": 0.1}` returned success and did nothing. All 28 call sites now route
   through the style-tolerant `arg()`.
2. **The guard for that had a hole.** rustfmt wraps long chains as `args\n    .get(`, which a substring
   check cannot see — 20 more sites were still broken while the guard reported clean. It now ignores
   whitespace.
3. **`probe_fits_pixel` reported no WCS on images that have one** — the payload set `"hasWcs": false`
   and then wrote `out["has_wcs"] = true` beside it, two different keys.
4. **`list_open_tabs` always returned empty arrays.** Its three setters had zero callers, so the
   snapshot was never written. Nothing noticed until this phase added tools that address a tab by index.

**Two 1.3.3 QA fixes ported:** blanked FITS pixels omit `value` (NaN is not representable in JSON, so
serializing one failed the whole call), and probing a strided cube used the resident array's bounds —
so on any downsampled cube most valid native spaxels reported "outside the cube", and those that did
answer read the wrong voxel. Native↔resident mapping is now two tested functions in `volume_data`,
shared by all three call sites that needed it.

**Source-level guards** now fail the build if a viewer host reads arguments with `args.get(` or emits a
snake_case JSON key. Unusual, but these hosts need a live GTK tree so they have no unit coverage, and
every bug above was silent by construction.

### Phase 4 — QA + reliability (S) — **DONE**
Q1–Q4 landed earlier (see §3d). The two remaining 1.3.2 items are now in:

- **Kernel deaths explain themselves.** `stderr` was discarded on the reasoning that the harness reports
  cell errors as JSON on stdout — true, but anything that kills Python BEFORE the harness runs is only
  ever explained on stderr, so the user got "exited unexpectedly" and nothing to act on. It is now
  captured and drained into the error, truncated to its tail where the cause lives.
- **Landing tiles reflow.** A fixed 3-column `Grid` clipped tiles on a narrow window and left later rows
  unreachable on a short one; now a `FlowBox` (3 → 1 per line) with horizontal scrolling refused outright.

**The reference's kernel restart race does not exist in this port**, and that was verified rather than
assumed: its bug was an exit-event handler resolving the harness file via a shared field. We have no such
handler, `&mut self` serialises starts on one service, and each launch writes a uniquely named harness so
per-tab kernels cannot collide. That uniqueness is now pinned by a test, since the whole argument rests
on it.

### Phase 5 — High-severity carry-overs (M) — **DONE**
**The CAOM2 cache was dead.** `CAOM2Service` carries a 100-entry LRU but was constructed fresh at every
call site, so every lookup missed and each observation-detail open re-issued the full 30–50s
`caom2ops/meta` request. It now lives in `AppServices`, shared by both callers.

**`download_observation` / `download_observations_bulk`** complete the tool surface at 137/137. Both are
non-destructive (they ADD to the library, so autonomy may apply them). An absent `artifactIndex` stays
absent rather than defaulting to 0 — 0 addresses a real artifact, so a default would silently pick one.
The bulk tool validates every item before queuing and names the failing index; on an apply failure it
reports how many actually landed.

Both sit on a new `services::observation_download` — the shared resolve → pick-artifact → stream →
register core the Research audit asked for, which had been written out three separate times with three
