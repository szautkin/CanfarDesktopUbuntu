# Verbinal → CanfarDesktop 1.3.3 — Parity Plan

_Started 2026-08-10 · Reference: CanfarDesktop **1.3.3** (`36ac1d8`)_

> **Status:** Phases 0 and 1 are **complete** (see below). The tool surface now advertises **113 of the
> reference's 137 names**, with the remaining 24 tracked by a build-enforced backlog that can only
> shrink. `cargo fmt`, `cargo clippy -- -D warnings` and 855 tests all pass. Next up: **Phase 2**.

This supersedes `PARITY_REVIEW.md`, which is **stale** — it was written 2026-07-07 against commit
`7396c0b`, before `e46607a` ("full CanfarDesktop 1.3.x parity sweep") and before the current working-tree
WIP. Roughly two thirds of the items it lists as missing are now implemented and wired. Treat this
document as the live checklist and `PARITY_REVIEW.md` as history.

## 1. Where we actually are

**Verified baseline (measured, not assumed):**

- `cargo check --all-targets` → clean. `cargo test --bin verbinal` → **841 passed, 0 failed, 2 ignored**.
- The working tree carries ~4,060 uncommitted insertions across 32 files, closing a large block of old
  review items: observation-note MCP tools, the research export bundle + VOSpace upload, extended CAOM2

  Compute settings group, socket-path resolution, a versioned `ObservationStore` envelope with

**1.3.2** (reliability) and **1.3.3** (MCP full-UI coverage) after that. The entire 1.3.3 delta is exactly
two commits, which makes it unusually tractable to port:

## 4. The plan

Ordered so that each phase leaves the tree shippable, and so the "100% MCP UI coverage" goal lands first.

### Phase 0 — Land the WIP (S) — **DONE**
Landed in four commits: the in-flight sweep, the 1.3.3 QA fixes, a tree-wide `cargo fmt`, and a
hygiene pass that made `cargo clippy -- -D warnings` pass for the first time on this branch.

Clearing the lint noise surfaced two real defects it had been hiding:
- **The stdio bridge test was talking to the developer's running app.** It isolated itself with
  `$XDG_RUNTIME_DIR`, but `socket_path()` deliberately ranks the uid-derived `/run/user/<uid>` higher
  (so the bridge still finds the app when a launcher strips the environment). On any systemd host the
  override did nothing. Added `VERBINAL_MCP_SOCKET`, an explicit full-path override that beats every
  other rule, and pointed the test at it.
- **`filter_to_adql` was compiled twice** — `search_page.rs` pulled it in via `#[path]` while
  `helpers/mod.rs` already declared it, so its 8 tests ran in duplicate. (This is why the unit count
  reads 849 → 841 across those commits; no coverage was lost.)

### Phase 1 — Wire-contract parity (M) — **DONE**
All 14 tools renamed to the reference's names, `clear_user_site` implemented, and the 3 macOS aliases
added — **113 tools advertised**. 108 payload keys plus 8 `required` entries converted to camelCase.

The contract is now enforced rather than asserted: `data/canfardesktop_1.3.3_tools.txt` holds the
reference's exact 137-name manifest, and a test diffs ours against it three ways — nothing extra,
nothing missing outside a documented `NOT_YET_PORTED` backlog, and no backlog entry that is secretly
already implemented. **That backlog may only shrink**; it currently holds exactly the 24 tools Phases
2, 3 and 5 will add, so those phases tighten the test automatically as they land.

Two things worth knowing for later work:
- Renaming the tools also renamed the ops sent over the viewer bridge (the notebook and FITS hosts map
  a tool name straight through as its op). `run_all_cells`, `clear_cell_outputs` and
  `list_fits_bookmarks` would have silently failed; the host arms were aligned so tool names and bridge
  ops remain one vocabulary. **Any future tool rename must check the bridge hosts.**
- `str_arg` existed in 11 copies, with six sibling accessors scattered similarly, all reading
  `args.get(key)` directly. They are now one implementation in `mcp::tools` routing through a single
  style-tolerant `arg()`, so a caller may send either `publisherId` or `publisher_id` — matching the
  reference's case-insensitive deserialization, and keeping every pre-rename caller working.

### Phase 2 — Search MCP full UI coverage (XL) — Windows `36ac1d8`
Fix the four blocking UI defects first, because three of the tools cannot be implemented correctly on top
of them: **S2** (show-columns, blocks `set_search_results_view`), **S3** (facet desync, blocks
`set_search_constraints`), **S5** (form restore, blocks `load_recent_search`), and **S4** (pixel-scale
range) as a correctness fix. Then add the `"search"` arm to the viewer bridge, a
`SearchPage::handle_viewer_command`, and `src/mcp/tools/search_ui.rs` with all 15 tools. A precise
per-tool implementation spec — Windows behaviour plus the exact Rust widget/function each must reach —
is in the Search audit and should be pasted into this file before work starts.
`remove_recent_search` / `clear_recent_searches` must be **Destructive** proposals that never auto-apply,
and the former must resolve its index to a stable `(searchedAt, summary)` key at plan time so list drift
between proposal and approval cannot delete the wrong entry.

### Phase 3 — FITS + Cube MCP full UI coverage (L) — Windows `27a4889`
New tools: `blink_fits_tabs`, `switch_fits_tab`, `set_cube_transfer`, `show_cube_spectrum`,

## 6. Suggested definition of done

- `tools/list` name set is **identical** to CanfarDesktop 1.3.3's, enforced by a test.
- Every payload key is camelCase, matching the reference field-for-field.
- Every UI action on the Search page, the FITS viewer and the Cube viewer is reachable over MCP.
- The 1.3.3 QA fixes are ported with regression tests.
- `CHANGELOG.md` claims 1.3.3 parity only once the above hold.
